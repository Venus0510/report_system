## 当前流程能覆盖使用场景吗？

**部分覆盖，但有几个关键断点。** 你的操作流程是：

> 浏览组件/板式 → 复制组件信息 → 粘贴到Claude → 结合用户内容生成报告

### 能用的部分

- **ui-lib/gallery.html** 有"复制组件信息"按钮，浏览体验好，支持实时切换风格预览
- **system_v2** 有完整的5步表单向导，能生成结构良好的提示词，嵌入组件HTML代码、版式约束、风格token
- 两套工具都能复制内容到剪贴板

### 关键断点

**1. "复制组件信息"复制的是元数据，不是AI真正需要的模板代码**

gallery.html 的 `copyComponentInfo()` 复制的内容是：
```
📦 组件: KPI 数字卡片
🆔 ID: kpi-card
📂 路径: ui-lib/components/kpi-card/
🔧 Props:
  - label (String) — 标签文本
  - value (Number) — 指标数值
...
```

但Claude生成报告真正需要的是 `template.html` 里的**实际HTML结构和CSS变量引用**。这个只能通过另一个按钮"复制代码"单独获取。业务同事需要点两次，还要自己拼装提示词。

**2. 组件、版式、风格三者无法一站式复制**

业务同事看好一个组合（比如 KPI卡片 + A4横版 + 商务蓝白），需要分别：
- 点组件 → 复制组件信息 → 再点复制代码
- 点版式 → 复制版式信息
- 点风格 → 复制风格信息
- 自己在Claude里手工拼装成完整提示词

没有"购物车"或"收藏篮"的概念，无法一次性导出选中组合。

**3. gallery.html 缺少"生成提示词"的出口**

gallery 只能浏览和复制原始信息，没有"用此组件生成报告"的快捷入口。业务同事看到喜欢的组件后，不知道下一步怎么让Claude用这个组件生成报告。

**4. system_v2 的5步表单向导对业务同事太重**

system_v2 是给运营/PM用的专业工具，需要填主题、受众、用途、逐页配置结构、上传数据源等。对只想快速试一个组件的业务同事来说，门槛太高。

---

## 优化建议

按优先级排序：

### 高优先级：让"复制组件信息"直接可用

在 gallery.html 的 `copyComponentInfo()` 中，**同时附带 template.html 的实际代码**，并包装成Claude可直接理解的提示词格式。让业务同事一次复制就能直接粘贴到Claude使用。

比如复制出来的内容变成：

```
【组件引用】KPI 数字卡片 (kpi-card)
请严格参照以下HTML结构生成报告，使用 var(--color-xxx) CSS变量引用，不要替换为具体色值。

```html
<div data-cid="kpi-card" class="bg-[var(--color-bg-card)] rounded-[var(--radius-lg)] p-6 ...">
  ...
</div>
```

Props: label(String), value(Number), unit(String), trend(String)
```

### 高优先级：增加"收藏篮" + 一键导出提示词

在 gallery 侧边栏底部加一个"已选清单"区域，用户可以：
- 浏览过程中把组件/版式/风格点"加入选择"
- 查看已选清单
- 一键"生成并复制提示词"——把选中项拼装成完整Claude提示词

### 中优先级：gallery 增加"用此组件生成报告"快捷入口

在每个组件/版式详情页加一个按钮"生成报告提示词"，弹出极简表单（只需要：报告主题 + 内容描述），自动生成包含组件代码+风格token的提示词，一键复制。

### 中优先级：统一 system_v2 和 gallery 的提示词格式

目前两套工具的提示词格式不一致。gallery 更偏向浏览，system_v2 更偏向编排。应该让 gallery 的复制输出和 system_v2 的提示词风格对齐，这样业务同事从 gallery 复制的信息也能在 system_v2 中作为起点继续深化。

## 当前"复制组件信息"内容的逐项拆解

以 KPI 数字卡片为例，当前复制出来的内容是：

```
📦 组件: KPI 数字卡片
🆔 ID: kpi-card
📂 路径: ui-lib/components/kpi-card/
📄 文件: template.html, component.js, component.css
🔧 Props:
  - label (String) — 标签文本
  - value (Number) — 指标数值
  - unit (String) — 数值单位
  - trend (String) — 趋势标签
📝 描述: 大数字 + 趋势标签 + 说明文字
```

对比 template.html 实际内容：

```html
<div data-cid="kpi-card" class="bg-[var(--color-bg-card)] rounded-[var(--radius-lg)] p-6 flex flex-col gap-3 shadow-[var(--shadow-card)]">
  <span class="text-xs font-semibold px-3 py-1 rounded-full w-fit" style="color:var(--color-primary);background:var(--color-primary-light)">环比 +12.5%</span>
  <div class="text-5xl font-bold" style="color:var(--color-primary)">3.28<span class="text-lg font-normal" style="color:var(--color-text-muted)">%</span></div>
  <p class="text-sm" style="color:var(--color-text-muted)">七日年化收益率</p>
</div>
```

---

## 差距分析：Claude需要的 vs 当前提供的

| Claude 生成报告需要的 | 当前复制信息有吗？ |
|---|---|
| 组件的 **HTML 结构**（div嵌套关系、Tailwind类名） | **没有** — 这是最关键的缺失 |
| **CSS变量引用规则**（`var(--color-primary)`而非 `#1e3a8a`） | **没有** — Claude不知道要这样写 |
| **Tailwind + inline style 混用模式**（布局用class，颜色用style） | **没有** — 这是组件库的核心设计规范 |
| `data-cid` 属性约定 | **没有** — 生成出来无法被预览页的inspector识别 |
| 组件的**视觉效果参考** | **没有** — 只有文字描述"大数字+趋势标签" |
| Props / 数据接口 | 有 |
| 组件名称和ID | 有 |
| 文件路径 | 有（但Claude访问不到本地文件，无实际意义） |

**结论：当前复制的信息对Claude来说，相当于给了一个API签名但没有给实现。** Claude知道这个组件"叫什么"和"接受什么参数"，但不知道"长什么样"和"怎么写HTML"。生成出来的报告视觉一致性无法保证。

---

## 四个关键缺失的详细说明

### 1. 没有HTML模板代码（最关键）

template.html 是组件库的"单一真相源"。没有它，Claude只能从Props反推HTML结构，每个组件的输出都不一样，丢失组件库统一风格。

### 2. 没有CSS变量规则

组件库的核心设计是：**颜色通过 `var(--color-xxx)` 引用，切换 `data-theme` 即可换肤**。但复制信息里完全没有提到这一点。Claude可能直接写死 `#1e3a8a`，导致换风格后颜色不变。

### 3. 没有混用约定

组件库的实际写法模式是：
- 布局（flex/grid/padding）→ Tailwind class
- 颜色（背景/文字/边框）→ inline `style="color:var(--color-xxx)"` 

这是因为 Tailwind CDN 的 JIT 无法动态识别 CSS 变量。当前复制的信息完全不提这个规则。

### 4. 没有 data-cid 约定

`data-cid="kpi-card"` 是预览页元素检查器的锚点，也是后续逐模块填充的关键标识。当前复制信息缺失。

## 改造建议

每个类型的"复制组件信息"应该包含 Claude 实际生成所需的全部内容。建议改成：

**组件类：**
- ✅ 保留：名称、ID、Props
- ➕ 新增：**template.html 完整代码**（含 data-cid）
- ➕ 新增：**CSS变量使用规则**（一行提示）
- ❌ 去掉：文件路径（Claude无法访问本地路径，无意义）

**版式类：**
- ✅ 保留：名称、ID、容器尺寸、翻页方式
- ➕ 新增：**skeleton.html 完整代码**（含关键CSS类名）
- ➕ 新增：**页面结构规则**（如 page-a4-landscape > content-area > page-footer）

**风格类：**
- ✅ 保留：CSS变量值列表（这个当前已经很好）
- ➕ 新增：**引用方式**：`<link rel="stylesheet" href="design-tokens/tokens.css">` + `<html data-theme="xxx">`

**图表类：**
- ✅ 保留：名称、Props
- ➕ 新增：**template.html 完整代码**（含ECharts初始化脚本）
- ➕ 新增：**ECharts CDN 引用**提醒

## 四个关键缺失的详细说明

### 1. 没有HTML模板代码（最关键）

template.html 是组件库的"单一真相源"。没有它，Claude只能从Props反推HTML结构，每个组件的输出都不一样，丢失组件库统一风格。

### 2. 没有CSS变量规则

组件库的核心设计是：**颜色通过 `var(--color-xxx)` 引用，切换 `data-theme` 即可换肤**。但复制信息里完全没有提到这一点。Claude可能直接写死 `#1e3a8a`，导致换风格后颜色不变。

### 3. 没有混用约定

组件库的实际写法模式是：
- 布局（flex/grid/padding）→ Tailwind class
- 颜色（背景/文字/边框）→ inline `style="color:var(--color-xxx)"` 

这是因为 Tailwind CDN 的 JIT 无法动态识别 CSS 变量。当前复制的信息完全不提这个规则。

### 4. 没有 data-cid 约定

`data-cid="kpi-card"` 是预览页元素检查器的锚点，也是后续逐模块填充的关键标识。当前复制信息缺失。

## 四个关键缺失的详细说明

### 1. 没有HTML模板代码（最关键）

template.html 是组件库的"单一真相源"。没有它，Claude只能从Props反推HTML结构，每个组件的输出都不一样，丢失组件库统一风格。

### 2. 没有CSS变量规则

组件库的核心设计是：**颜色通过 `var(--color-xxx)` 引用，切换 `data-theme` 即可换肤**。但复制信息里完全没有提到这一点。Claude可能直接写死 `#1e3a8a`，导致换风格后颜色不变。

### 3. 没有混用约定

组件库的实际写法模式是：
- 布局（flex/grid/padding）→ Tailwind class
- 颜色（背景/文字/边框）→ inline `style="color:var(--color-xxx)"` 

这是因为 Tailwind CDN 的 JIT 无法动态识别 CSS 变量。当前复制的信息完全不提这个规则。

### 4. 没有 data-cid 约定

`data-cid="kpi-card"` 是预览页元素检查器的锚点，也是后续逐模块填充的关键标识。当前复制信息缺失。
