# 金融会计事务所估值团队 — 项目进度与工时管理系统设计方案

---

## 一、痛点还原与核心矛盾

| 痛点 | 根因 |
|------|------|
| 忙季一天十几个项目，忘记建任务 | 建任务流程重，打开系统→填一堆字段→提交，成本高 |
| 忘记填报工时 | 工时系统与任务系统割裂，填工时是额外动作 |
| 每个人都很忙但看不出来 | 没有实时可视化的工作量视图 |
| 领导知道人在忙但不知道忙了什么 | 缺少结构化的任务→工时→报告链路 |
| 向上汇报难 | 数据散落在各处，汇总靠手工 |
| 任务零散，项目集下类型多 | 项目→任务类型→工时code的映射关系复杂 |
| 不想增加额外负担 | 任何增加步骤的方案都会被抵触 |

**核心设计原则：录入成本趋近于零，信息产出自动溢出。**

## 三、核心数据模型

### 3.1 项目集（Project）

| 字段 | 说明 | 示例 |
|------|------|------|
| project_code | 可charge的项目编号 | V2026-0042 |
| project_name | 项目名称 | XX基金年度估值 |
| client | 客户名 | XX资管 |
| status | 进行中/已结项 | 进行中 |

### 3.2 任务类型（Task Type）— 两级分类

**第一级：可Charge vs 不可Charge**

| 类别 | 工时性质 | 说明 |
|------|----------|------|
| 可Charge | 项目工时 | 有项目code，可向客户收费 |
| 不可Charge | 非项目工时 | 内部事务，不可收费 |

**第二级：具体任务类型**

| 分类 | 任务类型 | 可Charge | 默认项目Code |
|------|----------|----------|-------------|
| 项目类 | 公募基金估值 | ✅ | 按项目集走 |
| 项目类 | 私募基金估值 | ✅ | 按项目集走 |
| 项目类 | 专户估值 | ✅ | 按项目集走 |
| 项目类 | PE股权估值 | ✅ | 按项目集走 |
| 项目类 | 咨询 | ✅ | 按项目集走 |
| 项目类 | 摊余成本计量 | ✅ | 按项目集走 |
| 项目类 | 其他 | ✅ | 按项目集走 |
| 事务类 | 开会 | ❌ | INTERNAL |
| 事务类 | 签合同 | ❌ | INTERNAL |
| 事务类 | 投标 | ❌ | BID-XXX |
| 事务类 | 意向投标 | ❌ | BID-XXX |
| 事务类 | 培训 | ❌ | INTERNAL |
| 事务类 | 其他内部 | ❌ | INTERNAL |

### 3.3 任务（Task）

| 字段 | 说明 | 必填 | 默认值 |
|------|------|------|--------|
| id | 自动生成 | ✅ | - |
| project_code | 所属项目code | 条件必填 | - |
| task_type | 任务类型 | ✅ | - |
| title | 任务标题 | ✅ | 按模板自动拼 |
| assignee | 执行人 | ✅ | - |
| week | 所属周 | ✅ | 当前周 |
| est_hours | 预估工时 | ❌ | 按类型默认 |
| actual_hours | 实际工时 | ❌ | = est_hours |
| status | 待办/进行中/完成 | ✅ | 待办 |
| created_at | 创建时间 | ✅ | 自动 |
| completed_at | 完成时间 | ❌ | - |
| source | 创建来源 | ✅ | 周会/日常/批量 |

**关键设计：actual_hours 默认等于 est_hours。** 绝大多数情况下，估值任务的实际工时与预估工时接近。完成时只需打勾，系统自动用预估工时填报。只有在偏差大时才需要手动调整。

## 四、核心交互流程

### 4.1 周会快建任务 — "三秒一条"

**场景：** 周一早会，领导对着团队成员逐个分配本周任务。

**交互方式：结构化快填表（推荐）**

打开"本周任务"页面，每人一个卡片，卡片内是可快速添加的行：

```
┌─────────────────────────────────────────────────────────┐
│  📋 本周任务 — 2026年第24周（6/8 - 6/12）                │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  👤 张三                                                │
│  ┌───────┬──────────┬──────────┬──────┬──────┐         │
│  │项目Code│ 任务类型  │  备注     │预计工时│ 操作 │         │
│  │V26-0042│ 公募基金  │ 季末估值  │ 4h   │ ✕   │         │
│  │V26-0038│ PE股权   │ 新项目    │ 6h   │ ✕   │         │
│  │   +    │  ▼选择   │          │      │ 添加 │         │
│  └───────┴──────────┴──────────┴──────┴──────┘         │
│                                                         │
│  👤 李四                                                │
│  ┌───────┬──────────┬──────────┬──────┬──────┐         │
│  │项目Code│ 任务类型  │  备注     │预计工时│ 操作 │         │
│  │V26-0042│ 专户     │          │ 3h   │ ✕   │         │
│  │   -    │ 开会     │ 周三投标会 │ 2h   │ ✕   │         │
│  │   +    │  ▼选择   │          │      │ 添加 │         │
│  └───────┴──────────┴──────────┴──────┴──────┘         │
│                                                         │
│                          [ 保存本周全部任务 ]             │
└─────────────────────────────────────────────────────────┘
```

**关键交互细节：**

1. **项目Code输入：** 输入前2-3位即模糊搜索，从已有项目集匹配，选中后自动带入项目名
2. **任务类型选择：** 下拉菜单，按使用频率排序（最近用的排前面），支持键盘快捷选择
3. **备注：** 可选，不填也能提交
4. **预计工时：** 根据任务类型自动填默认值（如公募基金默认4h），可改可不改
5. **批量保存：** 一次保存所有人的所有任务

**交互方式备选：语音建任务**

领导在周会上直接说：
> "张三这周做V26-0042公募基金季末估值4小时，V26-0038 PE股权新项目6小时；李四做V26-0042专户3小时，周三投标会2小时。"

系统自动解析为结构化任务，领导确认后一键创建。

**交互方式备选：表格粘贴导入**

从Excel直接粘贴周会记录，系统按规则解析。

### 4.2 每日勾选完成 — "打个勾就行"

**场景：** 每天下班前或第二天早上，团队成员打开自己的任务清单，勾选已完成的任务。

```
┌─────────────────────────────────────────────────────────┐
│  ☀ 张三的今日任务 — 周二 6/9                             │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  本周任务：                                              │
│                                                         │
│  ☑ V26-0042 公募基金 季末估值          4h    ✅ 已完成   │
│  ☐ V26-0038 PE股权  新项目             6h    ⏳ 待完成   │
│  ☐ 开会 周三投标会                     2h    ⏳ 待完成   │
│                                                         │
│  ────────────────────────────────────                   │
│  今日新增：                                              │
│  ☐ V26-0051 咨询 XX客户咨询            3h    ⏳ 待完成   │
│                                                         │
│  ────────────────────────────────────                   │
│  今日工时汇总：4h（已完成）+ 11h（待完成）               │
│                                                         │
│               [ 全部标记为今日完成 ]                      │
└─────────────────────────────────────────────────────────┘
```

**关键交互细节：**

1. **勾选即完成：** 点一下勾选框，任务状态变为"完成"
2. **自动填工时：** 勾选后，系统自动按预计工时生成工时记录，挂到对应项目code
3. **调整工时（可选）：** 点工时数字可弹出微调，但**不是必选动作**
4. **今日新增：** 临时加塞的任务，可以在"每日任务"页面快速添加，流程同周会快建
5. **全部标记：** 如果今天所有任务都做完了，一键全部标记

**工时自动映射规则：**

| 任务完成时 | 系统自动做 |
|-----------|-----------|
| 可Charge任务 | 按 project_code + task_type + actual_hours 生成一条工时记录 |
| 不可Charge任务 | 按 INTERNAL/BID-XXX + task_type + actual_hours 生成一条工时记录 |
| actual_hours = est_hours | 默认，无需额外操作 |
| actual_hours ≠ est_hours | 需手动调整（可选操作，不是必选） |

## 五、防遗漏机制

忙季最大的问题是"忘记"。系统需要在不对用户增加负担的前提下，主动推动流程闭环。

### 5.1 忘建任务

| 触发 | 机制 | 交互 |
|------|------|------|
| 周会结束 | 领导保存后自动推送"本周任务清单"给所有成员确认 | 成员点开确认，如有遗漏可快速补一条 |
| 每日9:00 | 推送"今日待办"到成员 | 提醒今天要做什么 |
| 领导发现遗漏 | 在"本周任务"页面随时追加 | 同周会快建流程 |
| 成员临时接活 | "每日任务"页面底部 + 快速添加 | 3个字段：项目code + 类型 + 工时 |

### 5.2 忘填工时

| 触发 | 机制 | 交互 |
|------|------|------|
| 每日18:00 | 检测当日有未完成勾选的任务，推送提醒 | "你今天有3条任务未勾选，点击一键完成" |
| 每周五16:00 | 检测本周仍有未完成任务，推送汇总 | "本周你还有2条任务未勾选" |
| 每周一9:00 | 检测上周仍有未完成任务，标记为"未填报" | 领导驾驶舱显示红色警示 |

### 5.3 "我实在太忙了"兜底

提供一个**"一键全部完成"**按钮：将当天/当周所有未勾选任务批量标记为完成，工时按预估自动填入。

> 虽然精度会降低，但"有数据"远比"没数据"好。宁可工时精度是±1小时，也不能一整周0工时记录。

## 六、工时系统对接方案

### 6.1 如果有现有工时系统

**方案A：API直推（推荐）**
- 任务完成 → 自动生成工时记录 → 调用工时系统API写入
- 用户无需打开工时系统，完全无感

**方案B：CSV/Excel周期导出**
- 每周自动生成工时Excel（格式与工时系统导入模板对齐）
- 领导确认后一键导入工时系统

### 6.2 如果没有现有工时系统

本系统自带工时记录功能，按周/月自动汇总，导出即用。

### 6.3 工时记录结构

| 字段 | 说明 |
|------|------|
| date | 日期 |
| project_code | 项目code |
| task_type | 任务类型 |
| chargeable | 是否可charge |
| hours | 工时 |
| assignee | 人员 |
| source_task_id | 关联任务ID |
| status | 已提交/待提交 |

## 八、交互设计总结 — "三个三秒"原则

| 动作 | 目标耗时 | 说明 |
|------|---------|------|
| **三秒建任务** | ≤3秒 | 选项目code（搜索2字）→ 选类型（下拉1点）→ 保存 |
| **三秒打勾** | ≤3秒 | 打开今日清单 → 勾选 → 自动填工时 |
| **三秒看全貌** | ≤3秒 | 领导打开驾驶舱 → 一屏看清团队状态 |

**任何超过3秒才能完成的操作，都算设计失败。**

## 九、技术实现建议

### 9.1 推荐技术路线

| 层面 | 方案 | 理由 |
|------|------|------|
| 前端 | 企业微信/飞书小程序 | 团队已有使用习惯，无需下载新APP |
| 后端 | 轻量API + 数据库 | 结构简单，CRUD为主 |
| 工时对接 | API或Excel导出 | 取决于现有系统 |
| 通知 | 企微/飞书机器人推送 | 定时提醒、未完成提醒 |

### 9.2 为什么不直接用飞书多维表格/Excel

| 维度 | 多维表格/Excel | 专用系统 |
|------|---------------|---------|
| 建任务速度 | 需填多列，操作分散 | 结构化快填，3秒一条 |
| 打勾完成 | 需找到对应行修改状态 | 专属今日清单，一键勾选 |
| 工时自动映射 | 手工 | 自动 |
| 提醒推送 | 无 | 自动 |
| 领导看板 | 需手动做图 | 自动生成 |
| 移动端体验 | 表格操作不便 | 原生优化 |

> **短期（1-2周可用）：** 可以用飞书多维表格 + 自动化流程做 MVP，先跑起来
> **中期（1-2个月）：** 开发专用小程序/应用，体验质的飞跃

### 9.3 MVP方案：飞书多维表格 + 自动化

**快速上线的最小可行方案：**

1. **一张"任务表"**：项目Code、任务类型、执行人、周次、预估工时、状态、完成日期
2. **一张"工时表"**：从任务表通过飞书自动化规则自动生成（状态=完成时触发）
3. **一个飞书机器人**：每日推送今日待办、提醒未完成
4. **一个仪表盘**：按人/按项目聚合工时

> MVP限制：建任务仍需填表，但通过字段默认值和下拉可加速；打勾只需改状态列；工时自动生成。

## 十、落地节奏建议

| 阶段 | 时间 | 产出 | 核心验证 |
|------|------|------|---------|
