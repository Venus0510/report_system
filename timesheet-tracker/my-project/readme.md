

# 1、痛点还原与核心矛盾

| 痛点 | 根因 |
|------|------|
| 忙季一天十几个项目，忘记建任务 | 建任务流程重，打开系统→填一堆字段→提交，成本高 |
| 忘记填报工时 | 工时系统与任务系统割裂，填工时是额外动作 |
| 每个人都很忙但看不出来 | 没有实时可视化的工作量视图 |
| 领导知道人在忙但不知道忙了什么 | 缺少结构化的任务→工时→报告链路 |
| 向上汇报难 | 数据散落在各处，汇总靠手工 |
| 任务零散，项目集下类型多 | 项目→任务类型→工时code的映射关系复杂 |
| 不想增加额外负担 | 任何增加步骤的方案都会被抵触 |

# 2 需要跟踪的事情类型有，项目进度，投标项目进度，意向项目进度三大类，每个类型的字段和填写不尽相同，关注点不同，都可以创建子任务
三种类型（项目进度 / 投标项目进度 / 意向项目进度）的字段具体有哪些不同？比如：

- 项目进度：项目code + 任务类型 + 负责人 + 截止日期 + 预估工时
- 投标项目：是否需要"客户名称"、"投标截止日期"、"中标概率"等额外字段
- 意向项目：是否需要"意向来源"、"预计签约时间"等字段

# 3 MVP：做一个交互原型首页.html的mvp，后期会迁移到左边有二分之一版面的系统中，专注"看板→添加任务→打勾任务→生成默认/填工时"

因为大家都不愿意填写任务和工时，所以每周一开会时把事情讲完了就能快速创建任务，强制把这个事情做了，能批量行添加，先有项目集，再有任务，再分配到个人头上，可能每个人负责的是不同的项目和任务，还要考虑周中其他时间临时的任务，也要能加上。
想法是有2个tab维度数据，一个是项目（任务）视图，看到半月内所有项目任务进度情况，展示为甘特日历条，这个页面参考文件夹中《日历甘特图.png》文件的交互；一个是团队人员档期视图，热力图，知道团队成员忙闲程度，有多少任务数量在头上。
另外一块区域有本人自己本周待办事项，可能是一个一个小卡片或者一行行待办事项，操作尽量简单，打个勾勾就完成任务然后把工时填好了，工时填写是有另外一个页面，后期通过接口同步过去，
有个按钮打开弹窗快速批量创建任务
时间窗口 ，滚动14天， 前3+今天+后10
开会 → 批量派活（行式快填，项目集+时间自动继承上一行）
         → 同事打开首页 → 看团队概览条 + 自己日历
         → 每天干活 → 勾任务 → 默认或输小时数 → 回车完成
         
#  4 交互设计总结 — "三个三秒"原则

| 动作 | 目标耗时 | 说明 |
|------|---------|------|
| **三秒建任务** | ≤3秒 | 输入（模糊搜索2字）/选项目→ 输入/选任务类型→ 保存 |
| **三秒打勾** | ≤3秒 | 打开今日清单 → 勾选 → 自动填工时 |
| **三秒看全貌** | ≤3秒 | 领导打开首页 → 一屏看清项目和团队状态 |
