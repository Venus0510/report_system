# Timesheet Tracker 设计文档

## 概述

`timesheet-tracker.html` 是一个纯前端单文件应用，用于双周（14天）任务排期和工时管理。零依赖，无需构建工具，直接浏览器打开即可使用。

## 设计理念

### 极简主义

- **零外部依赖**：纯 HTML + CSS + vanilla JS，不引入任何第三方库或框架
- **单文件交付**：样式、结构、逻辑全部内联在一个文件中，方便分享和离线使用
- **IIFE 隔离**：所有 JS 逻辑包裹在 IIFE 中，不污染全局作用域

### 视觉设计

- **纸质质感**：采用暖白底（`#FBFAF7`）+ 浅米色背景（`#EFEDE7`），模拟纸张触感，降低长时间使用的视觉疲劳
- **CSS 变量体系**：通过 `:root` 定义 7 个语义变量（`--paper`、`--ink`、`--muted`、`--line`、`--weekend`、`--accent`），全局风格统一可控
- **衬线式排版**：标题使用高字重（680），日期数字使用等宽字体（`tabular-nums`）确保数值对齐
- **微交互**：按钮按下有 1px 位移反馈，hover 有过渡动画，拖拽有抓取光标变化

### 交互范式

- **拖拽即创建**：在时间网格空白区域横向拖拽直接创建任务，所见即所得
- **就地编辑**：拖拽任务条两端的把手调整日期范围，拖拽中间移动整段任务
- **点击表头分配工时**：点击某个日期表头弹出当天任务列表，为各任务分配当日工时
- **模态编辑器**：点击任务条打开详情弹窗，编辑名称、备注、颜色

## 架构设计

### 数据模型

```
periodStart : Date        — 当前窗口的起始日期（周一）
tasks       : Task[]      — 所有任务列表
overrides   : {k:v}       — 工时覆盖字典，key 为 "absDay:taskId"
drag        : Drag|null   — 当前拖拽状态
```

#### Task 结构

```typescript
{
  id:     string    // 唯一标识，timestamp+random 生成 (e.g. "t...")
  name:   string    // 任务名称
  notes:  string    // 备注
  start:  number    // 开始日期（绝对天数，从 epoch 算起的天数）
  end:    number    // 结束日期（绝对天数）
  color:  string    // 色板中的 hex 色值
}
```

#### 日期编码方案

所有日期以**绝对天数**（`toDayNum`）存储，消除时区问题：

```javascript
function toDayNum(d) {
  // 将 Date 转换为以 UTC 对齐的天数，消除本地时区偏移
  var x = new Date(d);
  x.setHours(0,0,0,0);
  return Math.round((x.getTime() - x.getTimezoneOffset()*60000) / 86400000);
}
```

### 状态机

```
load() → render() → [用户交互] → render() → save()
                        ↑                      |
                        └──────────────────────┘
```

所有状态变更遵循 `交互 → 修改数据 → render() → 持久化 save()` 的单向流，无虚拟 DOM，直接操作 innerHTML 全量重绘。

### 模块划分

| 模块 | 位置 | 职责 |
|------|------|------|
| 常量定义 | 顶部 | 窗口天数(14)、色板(6色)、行高(44px) |
| 日期工具 | `addDays`/`startOfWeekMon`/`toDayNum` | 日期计算和转换 |
| 状态层 | `tasks`/`overrides`/`drag` | 核心数据 |
| 派生计算 | `hoursFor`/`taskTotalHours`/`dayTotalHours` | 工时统计算法 |
| 渲染引擎 | `render()` | 全量重绘日期头、网格、底部栏 |
| 交互处理 | 事件监听器 | 拖拽、点击、导航 |
| 持久化 | `load()`/`save()` | localStorage 读写 |

### 工时分配算法

```
默认工时 = 8h ÷ 当天任务数      （平均分配）
实际工时 = overrides[k] 或 默认工时   （允许覆盖）
```

- 当某天没有任务时，该天显示空状态
- 当天任务工时总和超过 8h 时，弹窗中的计数器变红警告
- 工时覆盖在 `overrides` 中记录异常值；若用户设回默认值则删除该记录以节省存储

### 拖拽系统

| 模式 | 触发 | 行为 |
|------|------|------|
| `create` | 空白区域拖拽 | 拉出预览条，释放后新建任务并弹出编辑 |
| `move` | 拖拽任务条中间 | 水平移动整段任务 |
| `resize-l` | 拖拽左把手 | 调整开始日期 |
| `resize-r` | 拖拽右把手 | 调整结束日期 |

拖拽约束：
- 不超出当前窗口边界（`periodStartNum()` ~ `windowEndNum()`）
- 移动任务时长度保持不变
- resize 时不允许 end < start

### 弹窗系统

两个模态场景共享同一个 `#modalRoot` 容器：

1. **任务编辑器** (`openTaskEditor`)：编辑名称、备注、颜色，支持删除
2. **日期工时分配** (`openDayEditor`)：为当天各任务分配工时

弹窗采用固定定位 + 背景毛玻璃模糊遮罩，点击遮罩或按 Escape 关闭。取消新建任务时自动删除该任务（数据回滚）。

### 持久化策略

- 使用 `localStorage`，key 为 `timesheet_v1`
- 每次操作后立即 `save()`，保证浏览器崩溃不丢数据
- 存储最小数据：`tasks` 数组 + `overrides` 字典（不存派生数据）

## 关键设计决策

### 为什么不用框架

应用的核心复杂度在于拖拽交互和实时渲染，而非数据绑定或组件树。vanilla JS 直接操作 DOM 省去了框架的抽象层，且文件自包含无需构建。

### 为什么用绝对天数而非 ISO 字符串

- 日期跨度计算（`end - start`）变为简单整数减法
- 消除时区解析歧义
- 直接作为 `overrides` 字典的 key，查询 O(1)

### 为什么全量重绘

任务量通常 < 20 条，14 天固定窗口，innerHTML 全量重绘在毫秒级完成。相比增量 DOM diff，代码量显著更小、bug 更少。

### 网格布局方案

使用百分比定位（`left: x%; width: y%`）而非像素计算：
- 栅格自适应容器宽度
- 每列占 `1/14 ≈ 7.14%`
- 响应式友好，无需监听 resize 事件

### 色板设计

6 种预定义颜色（陶土、鼠尾草、石青、芥黄、梅紫、松绿），低饱和度风格，与暖色纸张背景协调。新任务按创建顺序自动轮换色板，用户可手动更换。

### 安全措施

- 所有用户输入文本通过 `esc()` 函数转义 HTML 实体，防止 XSS
- 弹窗打开时禁用底层拖拽交互，防止状态冲突
- `confirmClear` 二次确认防止误删
